# Migrating another machine to the new layout

Context: `main` used to be branch-per-OS (`macos`, `arch`, `windows`), each with
independent, diverged history. It's now a single branch with `common/` +
`macos/`/`linux/`/`windows/` stow packages. Both macs are cut over now - the
work laptop first, then the personal one (see git log on `main`). This doc is
the runbook for cutting over any remaining machine (Linux; Windows has no
bash/stow, see bottom).

**Lesson from the second mac**: `main` was built from the *first* machine's
state, so parts of the `macos/` package were silently machine-specific -
display regexes in `.aerospace.toml` that matched nothing on the second mac,
a `JAVA_HOME` pointing at a toolchain that wasn't installed, and a node setup
(asdf) that the other machine didn't use (fnm). None of it fails loudly. Diff
the package against the live machine file by file before cutting over, not
just the obvious files.

**Do this on a branch, not directly on `main`.** Push it, open a PR (or hand
it back for review) - don't merge to `main` unsolicited.

## Step 0: know what this machine actually has

Before touching anything:

```sh
git fetch origin
git log origin/arch..arch --oneline   # local commits never pushed
git status                            # uncommitted edits
```

Both are real risk: `main` was built from `origin/arch`'s last pushed state.
Anything only-local on this machine (commits or uncommitted edits) is
**not** reflected in `main`'s `linux/` package and will look like a
regression if you blindly switch over.

**Known risk to check specifically**: Hyprland config may have moved from
`.conf` to Lua on this machine. If `linux/.config/hypr/*.conf` in `main`
looks stale compared to what's actually running here, that migration
happened locally and was never pushed - don't discard it.

If you find real local drift: commit it to `arch` first (safety net, doesn't
touch anything live), then build a small worktree off `main` and port the
relevant files into `linux/` the same way the macos cutover reconciled its
own drift (see commits "Reconcile uncommitted live-machine drift..." and
"Restore .claude tooling..." on `main` for the pattern - diff old vs new,
pull forward what's real, drop what's actually dead).

## Step 1: create your working branch

```sh
git checkout -b migrate-arch origin/main
```

## Step 2: inventory live symlinks before removing anything

```sh
find ~ -maxdepth 1 -type l -exec ls -la {} \;
find ~/.config -maxdepth 1 -type l -exec ls -la {} \;
```

Note every symlink that points into the old dotfiles checkout. You'll need
to recreate the equivalents via `install.sh` after cutover - anything it
doesn't recreate (because the source file was intentionally dropped, e.g.
the old `dev.sh` no longer exists for macOS) is expected, not a bug.

## Step 3: rescue untracked-but-real app state

Anything gitignored that lives under the old `~/.config/*` on disk (auth
tokens, caches, browser/extension state - things regenerated by real usage,
not by git) needs to survive the switch. Move it aside before removing
symlinks, move it back into the fresh `~/.config` after `install.sh` runs.
`git status --ignored` in the old checkout will show you what's there.

## Step 4: cut over

```sh
rm ~/.config ~/.zshrc ~/.gitconfig   # only the symlinks - real files stay in the repo
git checkout migrate-arch
./install.sh --identity <work|personal>   # pick whichever this machine actually is
```

Then move the rescued app state back into `~/.config`.

## Step 5: verify

```sh
find ~ -maxdepth 1 -type l ! -exec test -e {} \; -print   # dangling symlinks
find ~/.config -maxdepth 1 -type l ! -exec test -e {} \; -print
zsh -i -c 'echo OK'                  # zshrc loads clean
git -C ~/dotfiles config user.email  # resolves to the identity you picked
```

## Step 6: push and hand back

```sh
git push -u origin migrate-arch
```

Then hand back for review/merge into `main` - don't fast-forward `main`
yourself.

---

## Windows

No bash, no stow. `windows/.glzr/glazewm/config.yaml` and
`windows/.glzr/zebar/settings.json` (+ `.marketplace/`) need to be copied
into place manually, or via a PowerShell script if one gets written later.
Not covered by this runbook.
